# 信号层说明（SIGNAL）

这份文档只讲一件事：**卡片上那个「预期次日 −31bp」到底是怎么算出来的**。
读完你应该能自己验算表里每一行，并且知道哪一步是估计、哪一步是假设。

---

## 0. 一句话版本

信号不是"预测收益率"，而是：**把当天所有可激活的因果机制，各自「读数偏离 × 敏感度 × 先验权重」加起来**。
加总前的每一行（bp）才是有信息的，加总后的 α 只是它的有界单调压缩。

---

## 1. v1 错在哪

v1 的聚合函数长这样（`legacy_v1_causual.py` 第 519 行）：

```python
def compute_alpha_macro(active_edges, edge_effects, current_state):
    total = 0.0
    for e in active_edges:
        effect = edge_effects[key]["by_regime"].get(current_state, overall)
        total += effect
    return tanh(total)
```

右边只有 `current_state` 和 `edge_effects`，**两者都是全样本一次性估出来的标量，没有 t**。
所以：

$$
\alpha(t) = \tanh\Big(\sum_{e\,:\,r\in \text{regime\_valid}(e)} \bar\tau_e(r)\Big)
$$

等式右边每一项都与时间无关 → 全样本 2815 个交易日，α 只有 **3 个取值**。
由此产生的连锁后果：

| 后果 | 说明 |
|---|---|
| "IC 评估"无效 | `pearsonr(alpha, future_ret)` 实际是"3 组 regime 均值与日收益"的相关 |
| `alpha > 0.05` 的样本筛选用来筛 regime | mask 不是选信号强度，是选状态 |
| 无法归因 | 同一天所有边的贡献是常数，无法回答"今天是谁在推" |

更根本的问题：论文的效应函数是 $f_{ij}(x, r)$，**两个自变量**。
v1 保留了 $r$，把 $x$（当期读数）丢了。这是一个建模错误，不是实现 bug。

## 2. 现在的公式

对每条已经估出参数的边 $e$：

$$
\text{contrib}_e(t) \;=\; m_e \cdot \beta_e(r_t) \cdot z_e(t) \cdot g_e(t) \cdot a_e(t)
$$

$$
\text{predicted}(t) \;=\; \sum_{e:\,\text{target}=\text{GOLD\_CNY}} \text{contrib}_e(t)
\qquad
\alpha(t) \;=\; \tanh\!\big(\text{predicted}(t) / \kappa\big),\;\; \kappa = 1\%
$$

对应代码：`signal.build_bundle()`。

### 逐项拆解

| 符号 | 名称 | 单位 | 从哪来 | 是否随时间变 |
|---|---|---|---|---|
| $m_e$ | 先验权重 `magnitude` | 无量纲 [0,1] | `paths.EDGES` 里手写 | 否 |
| $\beta_e(r_t)$ | 敏感度 | %/1σ | DML 的 regime 交互项 | 只在 regime 切换时跳 |
| $z_e(t)$ | 读数偏离 | 无量纲 | 252 日滚动 z | 每日 |
| $g_e(t)$ | 事件门控 | {0,1} | 事件型边专用 | 事件窗口内 |
| $a_e(t)$ | regime 门控 | {0,1} | `regime_valid` | regime 切换时 |

#### 2.1 $m_e$：先验权重，**是我拍的**

```python
Edge(..., direction=-1, magnitude=0.90, ...)
```

这些数字（0.9 / 0.85 / 0.75 / …）**没有任何统计依据**，是我按"机制的重要性"给的主观先验。
它唯一的作用是决定各机制的**相对**权重。

- 改它会**线性**改变贡献：$m_e$ 从 0.9 改到 0.45，那条边的贡献直接减半。
- 它出现在卡片表格的「权重」列，就是为了让你能验算。
- 如果你不同意某个权重，改一个数字、重跑即可，不用碰模型。

> 这也是一个待改进点：更严谨的做法是等权，或者按样本外表现校准权重。
> 现在保留手写权重，是因为"央行购金"和"COMEX 库存"在机制上确实不该等权。

#### 2.2 $\beta_e(r_t)$：敏感度，单位是 **%／1σ**

含义：**处理变量（读数）每偏离 1 个标准差，次日金价变化多少 %**。

估计方式（`estimators.fit_dml_edge`）：

1. 处理变量 $T$ 先在**训练期内**标准化（减均值、除标准差），所以是"每 1σ"。
2. 结果 $Y$ = 次日金价收益（`lead`）或当日金价收益（`contemp`），单位 %。
3. 用 `LinearDML` 做双重机器学习：随机森林拟合 $E[Y|W]$ 和 $E[T|W]$，在残差上回归。
4. 修饰变量 $X$ = regime 独热（`transition`、`risk_on`，基准组 `risk_off`）。
   于是 $\beta$ 在每个 regime 下是一个独立的系数，带标准误。

所以 $\beta_e$ **只在两个时点跳变**：regime 切换时，以及每 126 个交易日一次的
**滚动重估**（v3.1）。日内不变化——这是有意的：日频数据里把 $\beta$ 做成逐日变化，
只会把噪声当成"时变敏感度"。

> 关于滚动重估：β 在重估边界会跳，可能让连续两天的 α 出现台阶。这是"参数更新"
> 的代价，不是 bug。卡片第 1 节的"模型时效"显示最近一次重估日，若距今过久
> （>250 天）会标 ⚠。

> 关于读数显示：季度变量与部分美盘变量会被前向填充，导致"变化量"恰好为 0。
> 卡片不会显示成 `0.000`，而是 `—（08-14 未更新）`——**前向填充的 0 不是"没有变化"，
> 是"没有新数据"**，两者对信号的含义完全不同。

#### 2.3 $z_e(t)$：读数偏离

```python
def rolling_z(s, win=252, minp=60):
    mu = s.rolling(win, min_periods=minp).mean()
    sd = s.rolling(win, min_periods=minp).std()
    return ((s - mu) / (sd + 1e-9)).clip(-4, 4)
```

三个细节：

- **窗口 252 日**（事件型 120 日），`min_periods=60`：前 60 个交易日没有 z，贡献为 0。
- **截尾 ±4**：防止单日极端值主导整张卡片。比如 2020-03 的美元荒，VIX 单日跳 40 点，
  不截尾的话一条边就能把 α 打满。
- **因果**：`rolling` 只回看，不 forward fill、不 bfill。所以是"当天收盘时能算出的读数"。

> 注意：$z$ 是相对**该变量自身历史**的偏离，不是相对金价。
> $z=-1.81$ 的意思是"ETF 流入比它自己过去一年的均值低 1.81 个标准差"。

#### 2.4 两个门控

| 类型 | 变量 | 逻辑 | 例子 |
|---|---|---|---|
| regime 门控（持续） | $a_e$ | role ∈ `regime_valid` | VIX→金价 只在 risk_off 生效 |
| 事件门控（脉冲） | $g_e$ | 事件后 `window_days` 内 = 1 | 地缘风险跳升后 4 天内贡献 |

事件型边的 $\beta$ 不是回归系数，而是 $\text{CAAR} / \text{window\_days}$
（把整个事件窗口的累计异常收益摊平到每天）。所以事件型边在窗口内每天贡献一个常数，
窗口外贡献 0。

## 3. 三个实现细节，以及为什么这么选

### 3.1 为什么只加"直接指向金价"的边

DAG 里有一条链：`USD_INDEX → USDCNY → GOLD_CNY`。
如果两条边都进 α，同一条路径会被算两次；而且 $\beta$ 的单位不同
（美元指数→人民币 是"点→%"，人民币→金价 是"%→%"），相加没有意义。

所以：

```python
DIRECT_TARGET = "GOLD_CNY"
...
if e.target == DIRECT_TARGET:
    total = total + contrib
```

上游边（`FED_RATE→REAL_YIELD`、`CPI→FED`、`USD_INDEX→USDCNY`）不进 α，
只在卡片第 4 节单独列出，作为"传导链背景"。

**代价**：没有做多跳路径积分。`FED 加息 → 实际利率上行 → 金价承压` 这条链的间接效应
不体现在 −31bp 里，只体现在"上游"表格和实际利率那条直接边里。
这是已知限制，不是疏忽。

### 3.2 为什么慢变量要 ÷21

分布滞后估出来的是**月度累积效应**：

$$
y_t^{\text{monthly}} = \alpha + \sum_{k=0}^{L}\beta_k x_{t-k} + \epsilon,\qquad
\text{cumulative}=\sum_k \beta_k \quad (\%/\text{月})
$$

而日频边的贡献是 **%/日**。直接相加，慢变量会被放大 21 倍。

所以 `beta_series` 里：

```python
if model.edge.estimator == "distributed_lag":
    return pd.Series(model.cumulative / MONTH_DAYS, index=df.index)  # MONTH_DAYS=21
```

**副作用**（要知道）：这等于把"未来一个月慢慢释放的效应"压成"每天等量释放"。
真实传导是有滞后分布的（第 0 个月 40%、第 1 个月 30%…），严格做法是按 lag 系数逐日释放。
现在是粗糙摊销，已在 CHANGES 里列为待改进。

### 3.3 为什么 tanh 后面要除 1%

纯尺度变换，没有任何统计含义：

- `predicted` 是"预期次日 %"，常见范围 ±1%，个别日子能到 ±3%。
- 除以 1% 再 `tanh`，得到一个 **有界、单调、可排序** 的数，落在 (−1, 1)。
- 1% 这个常数是我选的，目的是让常见的 ±1% 落在 α≈±0.76，方便读数。

α **不是概率，不是仓位，不是置信度**。它唯一的用途是：跨日比较大小、给出方向。
卡片现在把主指标改成"预期次日 bp"，α 降为兼容字段，就是因为 bp 更直观。

## 4. 算例：把卡片上的一行算一遍

取自 `output/cards/card_2026-10-16.md` 第 2 节：

```
| 投资需求：ETF 持仓变化 | 因果 | -4.354吨 | 5% | -1.81 | +18bp/σ | 0.65 | -21bp | ✓ |
```

| 项 | 值 | 来源 |
|---|---|---|
| $m$ | 0.65 | 我在 `paths.EDGES` 里写的先验 |
| $\beta$ | +18bp/σ = 0.18% | DML 在 risk_off 下的估计 |
| $z$ | −1.81 | ETF_FLOW 相对自身 252 日历史的偏离 |
| $a$ | 1 | ETF_FLOW 的 `regime_valid` 是全部状态 |
| $g$ | 1 | 不是事件型边 |

$$
\text{contrib} = 0.65 \times 0.18\% \times (-1.81) = -0.212\% = -21\text{bp}
$$

**注意**：如果你漏掉权重，会算成 $0.18 \times (-1.81) = -33\text{bp}$，和表里的 −21bp 对不上。
所以卡片把「权重」单独列出来——这一类对不上账的问题最容易被当成 bug。

解释：ETF 流入处在过去一年最低的 5% 分位（z=−1.81），而在当前状态下
"每 1σ 的流入对应 +18bp 的金价"，所以"流入极低"这个读数翻译成 **−21bp 的下行贡献**。

11 条直接边加总：−31bp。α = tanh(−0.31 / 1.0) = −0.30。

## 5. 五个常见误读

**1）「预期次日 −31bp」不是收益率预测。**
它是"如果这些机制的历史平均效应成立，明天金价会往哪边偏、偏多少"。
没有标准差，没有概率，没有置信区间。想看不确定性，看卡片第 6 节（换口径后变多少）
和第 8 节（单条读数再动 1σ 会怎样）。

**2）$z$ 是相对自身历史，不是相对金价。**
z=−0.73 的 USDCNY 意思是"人民币比它自己过去一年均值低 0.73 个标准差"，
不是"人民币和金价的关系偏离 0.73"。

**3）$\beta$ 不显著时，贡献仍然是点估计，照样进 α。**
卡片用「—」标记（95% CI 覆盖 0），但数字仍然相加。这是刻意的：
如果只让显著的边进 α，等于用估计结果反过来筛模型，会让 α 的方差更大、更难复现。
代价是噪声大——现在 11 条边里有 8 条不显著，α 的相当一部分是噪声。

**4）关联层（情绪/仓位）的 $\beta$ 更弱、更容易失效。**
`OPEN_INTEREST`、`ETF_PREMIUM` 与金价在同一时点被共同决定，估出来的
"次日效应"只是同期关联里滞后释放的那一小部分。所以它们标"关联"，
且卡片第 6 节会告诉你"去掉这两条后 α 变成多少"。

**5）α 的绝对值没有含义。**
α=−0.30 不代表"30% 的看空概率"。它只有符号和相对大小的意义。

## 6. 和评估的连接：为什么用 Rank IC

- α 与 `predicted` 严格单调（tanh），所以两者的**排序完全一致**，
  用哪个算 Rank IC 结果一样。
- Rank IC = $\text{Spearman}(\alpha_t,\; r_{t+h})$。
  它衡量的是"信号排序"与"未来收益排序"的一致性，对极端收益不敏感——
  这正是我们想要的，因为 α 本身就是个趋势/方向判断，不是幅度预测。
- **单品种没有横截面**，所以这是时序秩相关，不是标准的截面 IC。
  截面 IC（每天对多品种排序）要等扩展到金银双品种才有意义。
- 置信区间用**按 20 日块重采样**的 bootstrap：日频收益强自相关，
  朴素的 p 值（假设 iid）会明显高估显著性。

### 6.1 信号时点：这里有一个能把 IC 从 0 抬到 0.5 的坑

`contrib_e(t)` 用的是 t 日行。但**美盘变量的「t 日」收盘发生在上金所 15:30 收盘之后**：

| 变量 | t 日数值实际可得时间（北京） |
|---|---|
| 上金所收盘价、沪金持仓量 | t 日 15:30 |
| COMEX 金价（session 标注为 t） | t+1 日约 05:00 |
| 10Y 实际利率、VIX、美元指数 | t+1 日约 05:00 |
| USDCNY（H.10 的 NY noon） | t+1 日约 00:00 |

所以「用 t 日面板算出的 α，去预测 t+1 的收盘→收盘收益」是**前视的**。
实测：这样算出来 Rank IC 0.53；把面板整体右移一天后掉到 **−0.03**。
也就是说那 0.5 几乎全部来自时区泄漏。

现在代码里的处理：

- 结构 β 仍在**同期面板**上估计（要估的就是同一天内的传导）；
- 信号提供 `SIGNAL_LAG_DAYS` 开关，并且明确**执行时点是 t+1 开盘**；
- 评估同时报两个口径：
  - `fwd{h}`：收盘→收盘，**不可直接交易**，只作参照；
  - `fwd_oc{h}`：开盘 t+1 → 收盘 t+h，对应「t+1 开盘执行」。

⚠ 仍未解决：上金所 Au99.99 早盘流动性薄，日开盘价常等于前收，
`fwd_oc` 里混入隔夜跳空，0.44 的 Rank IC 很可能仍是口径造成的假象。
要用它做交易决策，需要分钟级数据重新对齐 session，或者改用期货连续合约的开盘价。

## 7. 卡片上数字不对时，按这个顺序查

1. **看 $z$**：是不是被截到 ±4 了？是不是落在 `min_periods=60` 之前的 NaN 区？
2. **看 $\beta$**：`beta_series` 用的是该日的 regime 独热。regime 来自 walk-forward HMM，
   查它是否在 `when` 附近刚切换过（切换当天 β 会跳变）。
3. **看权重和层**：$m$ 是不是记错了？这条边是不是 associative（第 6 节会剔除它）？
4. **看门控**：事件型边是否在窗口内？`g=0` 时贡献一定是 0。
5. **看单位**：`contrib` 存的是 %，卡片显示时 ×100 变成 bp。
   所有"差 100 倍"的困惑都来自这里。
